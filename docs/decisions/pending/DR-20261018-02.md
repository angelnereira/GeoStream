# Solicitud de decisión DR-20261018-02

- **Abierta por:** agente de código
- **Fecha:** 2026-10-18
- **Tarea afectada:** T-E8-04 / T-E8-05 (`POST /v1/edge/reports`, almacenamiento opaco)
- **Condición de parada:** (1) contradicción entre documentos

## Qué se encontró

`docs/11_DATA_STORAGE.md` §2.0 define la tabla `edge_reports` con una columna
**obligatoria** para el buscador:

```sql
CREATE TABLE edge_reports (
    ...
    finder_device_id uuid NOT NULL,
    finder_ephemeral_pub bytea NOT NULL,
    ...
);
```

`docs/25_EDGE_DEVICES.md` §2.4 y el contrato
(`contracts/openapi/geostream.v1.yaml`, `postEdgeReport`) dicen lo contrario:

> El reporte **no** almacena `device_id` ni `subject_id` del buscador junto al
> blob (T-28): solo un `hashed_eid` y una marca temporal gruesa.

El vector `EDGE-RPT-*` de `contracts/test-vectors/edge_reports.json` también exige
que el servidor no pueda vincular el reporte al buscador.

Guardar `finder_device_id` junto al `ciphertext` es precisamente el vínculo que
T-28 prohíbe: quien lea la base sabría **qué dispositivo** vio el tag y **cuándo**,
aunque no pueda descifrar el blob.

## Por qué bloquea

No se puede escribir el endpoint cumpliendo las dos cosas a la vez: la migración
exige la columna `NOT NULL` y la política prohíbe guardarla. Implementar una
viola la otra, y el agente no elige.

## Opciones

1. **La política manda (recomendada).** Se corrige `11` §2.0: `edge_reports`
   pierde `finder_device_id` y se queda con `hashed_eid`, `finder_ephemeral_pub`,
   `payload_salt`, `ciphertext`, `time_bucket`, `expires_at`. La tasa por
   (dueño, `hashed_eid`) de `25` §2.7 se lleva en el almacén efímero, que ya es
   el patrón del producto para los contadores. Requiere una migración `0006`
   (o editar `0005` si nadie ha desplegado).
2. **La migración manda.** Se documenta que el `finder_device_id` se guarda y se
   **explicita** el riesgo en `25` §2.4 y en `10`; habría que justificar por qué
   T-28 no aplica a esta tabla. Impacto: contradice el vector `EDGE-RPT-*` y la
   promesa de no vinculabilidad, así que habría que cambiar también el contrato.
3. **Seudonimizar.** Se guarda un `HMAC(k_tenant, device_id)` en lugar del
   `device_id` crudo. Permite la tasa por buscador sin guardar su identidad, pero
   `k_tenant` es una clave más que custodiar y el vínculo sigue existiendo dentro
   del tenant.

## Recomendación del solicitante

**Opción 1.** La no vinculabilidad del buscador es la promesa de producto de esta
fase (`NFR-PRIV-004`) y el vector ya la fija; una columna heredada no debería
ganarle. La tasa por buscador se resuelve en el almacén efímero, como el resto
de contadores del sistema, sin tocar la tabla duradera.
